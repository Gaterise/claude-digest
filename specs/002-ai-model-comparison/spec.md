# Feature Specification: AI モデル比較ページの日次自動更新とベンチマーク・話題モデル掲載

**Feature Branch**: `002-ai-model-comparison`  
**Created**: 2026-10-16  
**Status**: Draft  
**Input**: User description: "Claude モデル比較のページでは毎日一度チェックして記事更新してほしい。さらに各モデルのベンチマーク比較や他の話題のAIモデルの情報も見れるようにしてほしい。見やすいページとなるように必要であればスキルなども使うように。"

## Clarifications

### Session 2026-10-16

- Q: 毎日のチェックと更新の方式は？ → A: 既存のトレンド機能と同じく、サーバー側の定期処理で検索付き AI に最新情報を調べさせ、保存したデータをページに表示する
- Q: 「記事更新」の範囲は？ → A: ページ内のデータ更新のみ（ダイジェスト記事の作成や通知は行わない）
- Q: ベンチマークの対象は？ → A: AI がその時点で注目されているベンチマークを選んで比較する
- Q: 他の話題の AI モデルの範囲は？ → A: ベンダーを固定せず、AI がその時点で話題のモデルを5件程度選ぶ
- Q: ベンチマーク表に載せるモデル範囲は？ → A: Claude モデルと話題の他社モデルを横並びで比較する
- Q: ベンチマーク値の信頼性担保は？ → A: 数値ごとに出典 URL を必須とし、出典がない値は「―」と表示する
- Q: ページ構成は？ → A: 1ページ内でタブ切替（Claude モデル / ベンチマーク比較 / 話題の AI モデル）※ 2026-10-19 に下記の2ページ構成へ変更
- Q: 更新時刻と失敗時の扱いは？ → A: 日本時間 午前6時に1日1回実行。失敗時は前回データを表示し続け、初回は現行ページの内容を初期データとして使う

### Session 2026-10-19（ページ分割）

- Q: ページ構成を見直すか？ → A: 2ページに分割する。`/models`「Claude モデル比較」は Claude モデルのみ（タブなし）。新設 `/ai-models`「話題の AI 比較」は「話題の AI モデル」（初期表示）と「ベンチマーク比較」の2タブ
- Q: ナビゲーションは？ → A: ヘッダーの3点メニューとフッターに「Claude モデル比較」「話題の AI 比較」の2リンクを並べる
- Q: 旧 URL（`/models?tab=benchmarks|trending`）は？ → A: `/ai-models` の該当タブへ恒久リダイレクトする
- 以降の本文で「タブ」「既定タブ」とある記述は、この決定により `/ai-models` の2タブ（既定: 話題の AI モデル）と読み替える。Claude モデルタブの要件（FR-006）は `/models` ページの要件とする

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 常に最新の Claude モデル情報を確認する (Priority: P1)

閲覧ユーザーがモデル比較ページを開くと、Claude の現行モデル（名称・モデルID・位置づけ・コンテキスト長・最大出力・価格・特徴・得意分野）が最新の状態で表示される。ページには「最終更新日」が表示され、情報の鮮度がわかる。

**Why this priority**: 現在のページは作成時点の情報で固定されており、新モデル登場や価格改定に追従できない。日次で最新化されることがこの機能の中核価値であり、これだけで MVP として成立する。

**Independent Test**: 定期更新処理を1回実行した後にページを開き、「最終更新日」が実行日になっていること、Claude モデル一覧とスペック比較表が表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 日次更新が成功しているとき、**When** ユーザーがモデル比較ページを開くと、**Then** 最新の Claude モデル一覧・スペック比較表・使い分けガイドが表示され、最終更新日が表示される
2. **Given** 新しい Claude モデルが公開された翌日、**When** ユーザーがページを開くと、**Then** 新モデルが一覧に含まれている
3. **Given** 当日の更新処理が失敗したとき、**When** ユーザーがページを開くと、**Then** 前回成功時のデータと前回の最終更新日がそのまま表示される
4. **Given** 一度も更新処理が成功していないとき、**When** ユーザーがページを開くと、**Then** 現行ページと同等の初期データが表示される

---

### User Story 2 - ベンチマークでモデルの実力を比較する (Priority: P2)

閲覧ユーザーが「ベンチマーク比較」タブを開くと、その時点で注目されている主要ベンチマークについて、Claude モデルと話題の他社モデルのスコアを横並びの表で比較できる。各スコアには出典リンクがあり、出典がない値は「―」と表示される。

**Why this priority**: スペックや価格だけでは性能差がわからない。客観的な数値比較はモデル選定に直結する高い価値を持つが、P1 のデータ更新基盤の上に成り立つ。

**Independent Test**: ベンチマーク比較タブを開き、ベンチマーク×モデルの表が表示され、各数値に出典リンクがあること、出典のない値が「―」で表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** ベンチマークデータが存在するとき、**When** ユーザーがベンチマーク比較タブを選ぶと、**Then** ベンチマーク名・その概要・各モデルのスコアが表形式で表示される
2. **Given** スコアが表示されているとき、**When** ユーザーがスコアの出典リンクを選ぶと、**Then** 出典ページが新しいタブで開く
3. **Given** あるモデルのあるベンチマークに出典付きのスコアがないとき、**When** 表が表示されると、**Then** そのセルは「―」と表示される
4. **Given** 各ベンチマークで最高スコアのモデルがあるとき、**When** 表が表示されると、**Then** 最高スコアが視覚的に強調される
5. **Given** スマートフォンで閲覧しているとき、**When** 表が画面幅を超えると、**Then** 表を横スクロールでき、ベンチマーク名の列は固定表示される

---

### User Story 3 - 話題の AI モデルを知る (Priority: P3)

閲覧ユーザーが「話題の AI モデル」タブを開くと、Claude 以外でその時点で話題になっている AI モデル（5件程度）について、提供元・概要・注目ポイント・公式情報へのリンクを日本語で確認できる。

**Why this priority**: Claude 利用者にとって競合モデルの動向把握は有益だが、本サイトの主目的（Claude 情報）に対しては補助的な価値のため P3 とする。

**Independent Test**: 話題の AI モデルタブを開き、5件程度のモデルカードが提供元・概要・注目ポイント・公式リンク付きで表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 話題モデルのデータが存在するとき、**When** ユーザーが話題の AI モデルタブを選ぶと、**Then** 各モデルの名称・提供元・リリース時期・概要・注目ポイント・公式リンクがカード形式で表示される
2. **Given** 日次更新で話題のモデルが入れ替わったとき、**When** ユーザーがページを開くと、**Then** 新しい顔ぶれが表示される

---

### User Story 4 - タブで見たい情報に素早く切り替える (Priority: P2)

閲覧ユーザーは1ページ内のタブ（Claude モデル / ベンチマーク比較 / 話題の AI モデル）で表示内容を切り替えられる。選んだタブは URL に反映され、共有や再訪時に同じタブが開く。

**Why this priority**: 情報量が増えるため、見やすさを保つには切替 UI が不可欠。US2・US3 の表示に必須の土台。

**Independent Test**: 各タブを選んで表示内容が切り替わること、URL にタブ状態が反映され、その URL を直接開くと該当タブが表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** ページを開いたとき、**When** タブ指定がないと、**Then** 「Claude モデル」タブが表示される
2. **Given** ユーザーが別タブを選んだとき、**When** 切替が完了すると、**Then** URL にタブ状態が反映され、ページ全体の再読み込みは発生しない
3. **Given** タブ状態付き URL を直接開いたとき、**When** ページが表示されると、**Then** 指定のタブが選択された状態で表示される
4. **Given** キーボードで操作しているとき、**When** 矢印キーでタブを移動すると、**Then** フォーカスと選択が移動する

---

### Edge Cases

- AI の応答が壊れている・必須項目が欠けている場合 → その区分の更新は破棄し、前回データを維持する
- Claude モデルが1件も取得できなかった場合 → 不完全なデータとみなし更新しない
- 話題モデルやベンチマークだけ取得に失敗した場合 → 取得できなかった区分は前回データを維持し、取得できた区分のみ更新する
- 出典 URL が http/https 以外、または形式が不正な場合 → そのスコアは出典なしとして「―」表示
- スコアの単位が混在する場合（%、Elo レーティングなど） → ベンチマークごとに単位を表示し、異なるベンチマーク間で比較しない
- ベンチマーク表のモデル数が多い場合 → 最大でも Claude 現行モデル＋話題モデル程度（10列前後）に収め、横スクロールで閲覧可能にする
- 不正なタブ指定の URL → 既定の「話題の AI モデル」タブを表示する（`/ai-models`）
- 外部リンクは新しいタブで開き、参照元情報を渡さない

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは1日1回（日本時間 午前6時）、Web 検索を用いて Claude モデル・注目ベンチマーク・話題の AI モデルの最新情報を自動収集しなければならない（MUST）
- **FR-002**: システムは収集結果を検証し、必須項目が揃った区分のみを保存しなければならない（MUST）
- **FR-003**: 更新に失敗した区分は前回成功時のデータを表示し続けなければならない（MUST）
- **FR-004**: 一度も更新が成功していない場合、現行ページと同等の初期データを表示しなければならない（MUST）
- **FR-005**: ページは最終更新日時を表示しなければならない（MUST）
- **FR-006**: Claude モデルタブは、各モデルの名称・モデルID・位置づけ・コンテキスト長・最大出力・入出力価格・説明・得意分野、スペック比較表、使い分けガイドを表示しなければならない（MUST）
- **FR-007**: ベンチマーク比較タブは、その時点で注目されるベンチマーク（3〜8件）について、Claude 現行モデルと話題の他社モデルのスコアを横並びの表で表示しなければならない（MUST）
- **FR-008**: すべてのベンチマークスコアは出典 URL を伴わなければならず、出典のないスコアは「―」と表示しなければならない（MUST）
- **FR-009**: 各ベンチマークは名称・概要（何を測るか）・単位を表示し、最高スコアを強調しなければならない（MUST）
- **FR-010**: 話題の AI モデルタブは、Claude 以外の話題モデル（3〜6件）について名称・提供元・リリース時期・概要・注目ポイント・公式リンクを表示しなければならない（MUST）
- **FR-011**: `/ai-models` は2つのタブ（話題の AI モデル〔既定〕/ ベンチマーク比較）で表示を切り替えられ、選択タブを URL に反映し、URL から復元できなければならない（MUST）。`/models` は Claude モデル情報のみをタブなしで表示し、旧タブ URL は `/ai-models` へリダイレクトしなければならない（MUST）
- **FR-012**: タブはキーボード操作と支援技術に対応しなければならない（MUST）
- **FR-013**: ページはスマートフォン幅でも崩れずに閲覧でき、幅の広い表は横スクロールできなければならない（MUST）
- **FR-014**: ページは情報が AI により自動収集されたものである旨と、公式情報の確認を促す注意書きを表示しなければならない（MUST）
- **FR-015**: 外部リンクは http/https のみ許可し、新しいタブで安全に開かなければならない（MUST）
- **FR-016**: 日次更新はダイジェスト記事の作成やプッシュ通知を行ってはならない（MUST NOT）

### Key Entities

- **ModelComparison（モデル比較スナップショット）**: ページ全体に表示するデータの最新版。Claude モデル一覧・使い分けガイド・ベンチマーク一覧・話題モデル一覧・区分ごとの最終更新日時を持つ
- **ClaudeModel（Claude モデル）**: ファミリー名・名称・モデルID・位置づけ・コンテキスト長・最大出力・入出力価格・説明・得意分野
- **Benchmark（ベンチマーク）**: 名称・概要・単位・各モデルのスコア（モデル名・数値・出典 URL）
- **TrendingModel（話題の AI モデル）**: 名称・提供元・リリース時期・概要・注目ポイント・公式 URL

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ページの最終更新日が、通常運用時に常に直近24時間以内（最大でも48時間以内）である
- **SC-002**: 新しい Claude モデルが公開されてから36時間以内にページへ反映される
- **SC-003**: 表示されるベンチマークスコアの100%が出典リンクを持つ（出典のない値は数値として表示されない）
- **SC-004**: 更新処理が失敗した日でも、ページは100%の確率で前回データを表示し、空表示やエラー表示にならない
- **SC-005**: ユーザーはページを開いてから1クリック以内に目的のタブ（ベンチマーク・話題モデル）に到達できる
- **SC-006**: 幅 375px のスマートフォン表示で、横方向のはみ出しによるレイアウト崩れが発生しない（表内の横スクロールを除く）

## Assumptions

- 情報収集には既存のトレンド機能と同じ Web 検索付き AI を使い、追加の外部有料サービスは導入しない
- 「Claude 現行モデル」はその時点で一般提供されている最新の各ファミリーの代表モデルを指し、旧バージョンは注記で言及するにとどめる
- ベンチマークスコアはベンダー公式発表または著名なリーダーボードを出典とすることを AI に指示するが、最終的な正確性は保証せず注意書きで補う
- 管理画面や手動での承認フローは対象外とする
- 既存のサイトデザイン（配色・カードスタイル・ヘッダー/フッター）を踏襲する
- 閲覧は登録不要の公開ページとする
